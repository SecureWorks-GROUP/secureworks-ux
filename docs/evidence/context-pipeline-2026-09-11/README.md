# Context pipeline panel: local proof

The existing JARVIS Context view now mounts a company-wide pipeline section. Database switches and effective lanes are read-only. Shared model calls are shown separately from extraction slots; unavailable budget data is not zero. Queue, source-time gaps, ready-job lower bounds, coverage, weekly accuracy and pending notification records keep their separate meanings.

The weekly reviewer loads the stored sample through `context_accuracy_sample`. It shows 40 requested alongside the actual sample, missing and unjudged counts. Each source-backed fact has an explicit human verdict. Only a false verdict enables the invented-payment checkbox. The existing `opsAuthHeaders` and `opsPost` transport supplies the signed-in token; no `judged_by` identity is submitted. B4 must derive and authorise the actor server-side. Saving reads the sample back, then refreshes pipeline status. Service credentials are not a substitute for a human session.

Business-event date presentation now uses `event_at`. A missing source date is not replaced by ingestion time. The matching backend projection is owned by the backend lane.
